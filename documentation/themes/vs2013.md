# VS2013 Theme

`Dirkster.AvalonDock.Themes.VS2013` provides the flat, crisp Visual Studio 2013 aesthetic in **Dark**, **Light**, and **Blue** palettes, targeting `.NET Framework 4.8` (`net48`) exclusively with zero external NuGet dependencies. In AvalonDock v5, all three variants inherit from `DictionaryTheme` and construct frozen `SolidColorBrush` dictionaries at runtime from embedded, GZIP-compressed `.vstheme.gz` resources (`#572`), eliminating thousands of lines of duplicated XAML brush dictionaries while preserving exact VS2013 control templates and docking indicators.

---

## Installation

```bash
dotnet add package Dirkster.AvalonDock.Themes.VS2013
```

## Usage

### XAML

```xml
<Window x:Class="MyApp.MainWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        xmlns:avalonDock="https://github.com/Dirkster99/AvalonDock"
        xmlns:vs2013="clr-namespace:AvalonDock.Themes;assembly=AvalonDock.Themes.VS2013">

    <avalonDock:DockingManager x:Name="dockManager">
        <avalonDock:DockingManager.Theme>
            <vs2013:Vs2013DarkTheme />
            <!-- Or: <vs2013:Vs2013LightTheme /> -->
            <!-- Or: <vs2013:Vs2013BlueTheme /> -->
        </avalonDock:DockingManager.Theme>

        <!-- Layout -->
    </avalonDock:DockingManager>
</Window>
```

### Code-Behind

```csharp
using AvalonDock.Themes;

dockManager.Theme = new Vs2013DarkTheme();
dockManager.Theme = new Vs2013LightTheme();
dockManager.Theme = new Vs2013BlueTheme();
```

## v5 Architecture & Migration Note

{: .warning }
In AvalonDock v4, `AvalonDock.Themes.VS2013` shipped loose XAML files such as `DarkBrushs.xaml`, `LightBrushs.xaml`, `BlueBrushs.xaml`, and `DarkTheme.xaml`. Those XAML files were **removed in v5** (`#572`) when the package moved to embedded `.vstheme.gz` resources (`vs2013dark.vstheme.gz`, `vs2013light.vstheme.gz`, `vs2013blue.vstheme.gz`). Any v4 custom theme attempting to merge those removed `AvalonDock.Themes.VS2013` XAML dictionaries will throw `IOException` at runtime.

The compiled XAML dictionaries remaining in `AvalonDock.Themes.VS2013` are:

- `/AvalonDock.Themes.VS2013;component/Themes/Generic.xaml` — VS2013 control templates
- `/AvalonDock.Themes.VS2013;component/OverlayButtons.xaml` — VS2013 docking target button styles

*(Note: the internal palette loader classes `VsThemeResources` and `VsThemePaletteFactory` inside `AvalonDock.Themes.VS2013` are `internal` implementation details and are not part of the public API.)*

## Customizing VS2013 Brushes at Runtime

Because `Vs2013DarkTheme`, `Vs2013LightTheme`, and `Vs2013BlueTheme` inherit from `DictionaryTheme`, each instance exposes its pre-populated `ThemeResourceDictionary` publicly (with all default `SolidColorBrush` entries pre-frozen). You can override any `AvalonDock.Themes.VS2013.Themes.ResourceKeys` brush before assigning the theme to `DockingManager.Theme`:

```csharp
using System.Windows.Media;
using AvalonDock.Themes;
using Vs2013Keys = AvalonDock.Themes.VS2013.Themes.ResourceKeys;

var theme = new Vs2013DarkTheme();

var customAccent = new SolidColorBrush(Color.FromRgb(0xE0, 0x6C, 0x75));
customAccent.Freeze();

theme.ThemeResourceDictionary[Vs2013Keys.ControlAccentBrushKey] = customAccent;
theme.ThemeResourceDictionary[Vs2013Keys.DocumentWellTabSelectedActiveBackground] = customAccent;
theme.ThemeResourceDictionary[Vs2013Keys.ToolWindowCaptionActiveBackground] = customAccent;

dockManager.Theme = theme;
```
